# Переработка Pozor.me

Основание: план переработки от 1 ноября 2026. Ветка: `codex/architecture-humor-v2`, база: `origin/main` (`6ecf1e7`). Пользователь запросил один итоговый PR в main; предложенные в документе маленькие PR заменены последовательными коммитами.

## Этапы

1. Зафиксировать исходные проверки, выделить core / infra / presentation / app, добавить проверку зависимостей и единый `poe check`.
2. Исправить retrieval, объединить права на источники, исключить ботские сообщения и исправить загрузку истории.
3. Ввести реестр и сервис настроек, приоритет сохранённых Telegram-реквизитов, единый CLI.
4. Реализовать движок юмора: уровни, зацепки, кандидаты, судья, постоянный антиповтор, журнал и оценки.
5. Объединить админку и бота одним event loop и очередью, усилить вход и CSRF, обновить Docker и CI.
6. Проверить миграции, offline suite, сборку и диагностику, опубликовать PR и итоговый отчёт.

## Границы проверки

Реальные истории и секреты не включаются в репозиторий. Запрошенный набор из 60 реальных обезличенных ситуаций нельзя подменять синтетикой: синтетический набор проверяет контракт, а качество и слепой win-rate требуют человеческих оценок. Замеры GPU, сравнение весов и групповые Telegram-сценарии отмечаются отдельно от offline проверок.
