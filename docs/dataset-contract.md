# DATA-01. Источники и формат примера

20 ноября 2026 года владелец согласовал формат 0.1 для первой выборки. В нём сохраняются контекст с говорящими и связями, действие `speak` или `skip`, источник и права, связь адаптации с оригиналом и отдельные оценки. Формат разобрали на вымышленной сцене о погодном приложении. Владелец выбрал поиск готового корпуса с открытой лицензией и проверку качества русских реплик.

## Доступ к материалам

**X / Twitter.** В X API поле `conversation_id` указывает на корневой пост, а элемент `referenced_tweets` с типом `replied_to` — на непосредственного родителя. Для нескольких уровней нужно проходить эти связи. Соседний по времени пост может относиться к другой ветке. Чтение по ID требует авторизации. Пункт III.A(k) Developer Agreement запрещает использовать X API и контент X для дообучения foundation models. Из этого следует, что стандартные условия разработчика не подходят для планируемого дообучения Gemma или Qwen. Покупка доступа к чтению эту проблему не решает. [Структура беседы](https://docs.x.com/x-api/fundamentals/conversation-id), [чтение поста](https://docs.x.com/x-api/posts/get-post-by-id), [X Developer Agreement](https://docs.x.com/developer-terms/agreement)

**Reddit.** У комментария есть ID содержащего его поста и непосредственного родителя. Родителем может быть пост (`t3_`) или другой комментарий (`t1_`). Для Data API Reddit требует предварительное одобрение и зарегистрированный OAuth-токен. Для обучения, включая некоммерческое, требуется отдельное явное разрешение Reddit. Условия Data API также требуют разрешения правообладателей соответствующих текстов. Это касается как целевого ответа, так и использованного в паре контекста. [Модель комментария](https://developers.reddit.com/docs/0.14/api/public-api/classes/Comment), [порядок доступа](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy), [Data API Terms](https://redditinc.com/policies/data-api-terms)

Без входа проверены открытые документы обеих площадок. Выборку из их пользовательских постов не собирали. Реальный доступ к русским текстам проверен на двух независимых открытых корпусах.

## Проверка русских реплик

20 ноября 2026 года скачаны файлы закреплённых версий без аккаунтов и оплаты. Codex прочитал 20 бытовых диалогов и 18 окон из пьес. Для каждой целевой реплики оценивал, понятны ли говорящий и повод, добавляет ли ответ комический ход и годится ли он в современную беседу в исходном виде. Человеческую реакцию и уместность инициативы корпуса не измеряют. Версии, SHA-256 исходных файлов и счётчики записаны в [manifest проверки](../examples/dataset/pilot-manifest.json).

| Источник | Происхождение и права | Что показала выборка |
| --- | --- | --- |
| **Russian Everyday Dialogues**, Екатерина Мыскина | Составитель указывает, что диалоги написаны носителем русского специально для коллекции, называет автора и прямо перечисляет дообучение среди назначений. CC BY 4.0 разрешает адаптацию с указанием авторства, лицензии и внесённых изменений при распространении. [Карточка автора и исходный файл](https://huggingface.co/datasets/kukunechka/russian-everyday-dialogues/tree/3d9c43ca85a50e7a32fa7b05e27c0637a710e988), [лицензия](https://creativecommons.org/licenses/by/4.0/) | Проверены все 20 пар, в том числе 7 в магазине, 7 в кафе, 6 в транспорте. В 19 ответ прямо продолжает бытовой разговор. В сцене о скидочной карте говорящий начинает как покупатель и заканчивает как сотрудник, предлагающий оформить карту. В 0 из 20 я нашёл контекстный комический ход. Это возможный контроль обычных ответов, материала для обучения юмору здесь не отобрано. |
| **RusDraCor**, А. П. Чехов, редакторы корпуса Франк Фишер и Даниил Скоринкин | Проверены заголовки TEI именно трёх отобранных пьес. В каждом указаны CC0 для публикации DraCor, первоначальное издание и статус public domain для цифрового источника — библиотеки Комарова. Для «Юбилея» в том же корпусе у первоисточника указана CC BY-SA 3.0, поэтому в однородную первую выборку он не вошёл. [Корпус и редакторы](https://dracor.org/rus), [исходные TEI-файлы](https://github.com/dracor-org/rusdracor/tree/cb06b3a211cc36ed0806c9ae85a94ede5da99557/tei), [CC0](https://creativecommons.org/publicdomain/zero/1.0/) | По 6 окон из «Медведя», «Предложения» и «Трагика поневоле». В 1 из 18 говорят три разных персонажа. В 2 из 18 можно адаптировать ход — собеседник отвечает на драматический монолог бытовой заботой о соседях или сорванной пуговице. Оба окна из одной сцены. В остальных 16 целевая реплика здоровается, возражает, требует или повторяет сказанное без самостоятельного панча. Готовых к прямому переносу в современный чат — 0 из 18. |

В бытовом корпусе `user` и `assistant` образуют явную пару, за пределами которой истории нет. В пьесах доступны персонаж, сцена и очерёдность. TEI не сообщает, на какую реплику технически отвечает персонаж. Сохраняем порядок и основание связи `sequence_only`. Участие нескольких персонажей само по себе не даёт метку адресата.

**Как повторить отбор RusDraCor.** Для трёх файлов в порядке manifest пройти сцены `div[type=scene]` внутри `body` в порядке документа. Если деления на сцены нет, весь `body` считается первой сценой. Внутри каждой пронумеровать элементы `sp` с единицы. Текст реплики составить из её `p`: убрать содержимое `stage`, сохранить текст после ремарки, свести пробельные последовательности к одному пробелу в каждом абзаце, соединить абзацы пробелом. Окно состоит из целевой реплики длиной 1–160 символов и двух непосредственно предшествующих реплик той же сцены. Во всех трёх есть текст и `who`, а у двух последних различаются `who`. Для каждой пьесы взять первые 6 окон после сортировки по SHA-256 от UTF-8 строки `<slug>/<номер сцены>/<номер целевой реплики>`. Slug получается из имени файла без `chekhov-` и `.xml`. Контрольная сумма ключей в manifest учитывает порядок файлов, порядок отбора и LF после каждого ключа. Получилось 289 подходящих окон, из них рассмотрены 18. Соседние окна могут пересекаться.

**Следующий объём.** Для бытового корпуса дальнейший сбор на юмор — 0, просмотрен весь файл. Для RusDraCor предлагается редакторская партия из 24 окон, по 6 из четырёх других комедий минимум двух авторов после проверки прав на тексты. Внутри каждой пьесы выбирать окна по тому же хешу, пропуская окна, которые делят реплику с уже выбранным окном. Такой объём позволит выяснить, повторяется ли пригодный приём вне единственной найденной сцены. Для каждой кандидатуры считать число разных сцен и время адаптации. При том же результате искать другой источник современного обмена репликами. Объём обучающего корпуса определится после оценки отредактированных пар. Согласование формата относится к структуре записи, оценок качества от владельца в этой проверке нет.

## Запись

Минимальный рабочий пример состоит из двух файлов. В [examples.json](../examples/dataset/examples.json) есть английский диалог, его русская адаптация и отдельная сцена с явно заданным молчанием. [Manifest](../examples/dataset/manifest.json) фиксирует состав и разрешённое назначение всей демонстрации. Все персонажи и реплики вымышлены.

| Поле | Смысл и проверка |
| --- | --- |
| `id`, `conversation_id` | Уникальный ID версии примера и стабильный ключ исходного разговора с пространством имён источника. Адаптация получает свой `id` и сохраняет `conversation_id`. |
| `language` | Язык этой версии. У перевода исходный язык доступен по связи с оригиналом. Для смешанного диалога язык уточняется на уровне сообщения. |
| `source` | Вид источника, ссылка на исходную запись и ключ основания использования `rights_ref`. У синтетики `url: null`. Для материала, переданного автором, вместо публичного URL достаточно проверяемой ссылки на закрытую запись выдачи прав. |
| `creation` | Способ создания (`original`, `generated`, `translation`, `adaptation` или `edit`), кто выполнил работу, ссылки `derived_from` на исходные примеры. Редактор адаптации не становится автором оригинальной реплики. |
| `context[]` | Известные к моменту решения сообщения в хронологическом порядке. У каждого есть `id`, `parent_id`, ключ говорящего `author` и `text`. ID сообщения уникален внутри исходного разговора. Ключ говорящего сохраняется в пределах сцены. |
| `response` | Для `speak` хранится текст следующей реплики с теми же полями сообщения. Для `skip` хранится только действие. Момент решения следует за последним сообщением контекста. Последующие реакции участников во вход не входят. |
| `annotations[]` | Оценки этой версии. Для каждой сохраняются источник (`human` или `model`), идентификатор оценщика, версия рубрики и отмеченные им признаки. Для модельной оценки нужны также версия модели и версия промпта. Пустой список означает, что пример ещё не оценивали. |

У известной корневой или самостоятельной реплики `parent_id` равен `null`. При известном, но недоступном родителе сохраняется внешний ID и причина пропуска в закрытой записи импорта. Если источник передаёт только порядок реплик, поле `parent_id` опускается и указывается `link_basis: sequence_only`. Пара с недостающим необходимым контекстом исключается из выгрузки. Реплики из соседней ветки и сгенерированные пересказы не заполняют пробел. Реальные платформенные ID, ссылки и авторство каждого исходного сообщения сохраняются в закрытом реестре происхождения. Из него можно найти **все** примеры, использующие сообщение в любом месте контекста или ответа.

Для оригинальной наблюдаемой пары наличие ответа говорит лишь о том, что участник его написал. Уместность вступления, зацепку и комический ход, ясность, силу выпада, реакцию оценщика и предложенную им редактуру размечают отдельно. Отсутствие следующего сообщения не образует метку `skip`. В демонстрации её явно задал составитель вымышленного сценария. Она не учитывается как человеческая оценка HUM-01.

## Формирование версии выборки

1. **Проверить основание.** Закрытый реестр по `rights_ref` хранит происхождение, применимые условия или разрешение, дату проверки, область действия и статус. Проверяются все исходные сообщения и операции над ними. Право на перевод, передачу внешнему оценщику и обучение проверяется в объёме конкретной операции. В данном manifest `fixture-only` разрешает только проверку контракта.
2. **Свести повторы.** Объединить повторные получения одного ID. В отдельном представлении для сравнения нормализовать Unicode и пробельные символы, сравнить хеши и проверить близкие копии. Исходное написание сохраняется. Для похожих фрагментов сопоставлять контекст вместе с ответом, сохранять связи подтверждённых копий, неоднозначные совпадения оставить на проверку.
3. **Разделить разговоры.** До назначения `train`, `validation` и `test` собрать в общую группу все версии одной беседы, её адаптации и подтверждённые копии в других беседах. Группа попадает в один раздел. Назначение фиксируется в manifest и сверяется с ранее отложенными беседами при добавлении материала. Для контрактных примеров выделен раздел `fixture`. Диалоги, отложенные для итогового слепого сравнения HUM-01, исключаются из обучения и настройки.
4. **Зафиксировать состав.** Manifest содержит версию схемы и набора, критерий отбора, файл и SHA-256, распределения по языкам, действиям и типам оценок, распределение разговоров по разделам. Для реального сбора дополнительно сохраняются закрытые сведения о версии сборщика, параметрах и времени отбора, версиях правил очистки и дедупликации, причинах отбраковки. В Git попадают только разрешённые агрегаты и вымышленные примеры. Рабочие записи и доказательства разрешений хранятся вне Git, например под игнорируемым `data/`.
5. **Обработать удаление.** При отзыве разрешения или удалении источника исключить его из новых выгрузок, найти по реестру затронутые контексты, ответы, адаптации и разметку. Удалить соответствующие тексты из рабочих копий согласно условиям источника, перевыпустить набор и отметить старую версию непригодной для дальнейшего использования. Если пользователь удалил аккаунт Reddit, из сохранённых записей также нужно удалить идентифицирующие сведения автора. Проверить по manifest, какие прогоны затронуты. Удаление строки из набора само по себе не удаляет влияние уже прошедшего обучения из весов. [Требования Reddit к удалению](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [требования X к обновлению и удалению](https://docs.x.com/developer-terms/agreement)

Контрольная сумма `sha256_utf8_lf` считается по содержимому UTF-8 без BOM с переводами строк LF. Эту проверку можно повторить из корня репозитория.

```powershell
@'
import json
from hashlib import sha256
from pathlib import Path

directory = Path("examples/dataset")
manifest = json.loads((directory / "manifest.json").read_text(encoding="utf-8"))
payload = (directory / manifest["file"]).read_text(encoding="utf-8")
assert sha256(payload.encode("utf-8")).hexdigest() == manifest["sha256_utf8_lf"]
assert len(json.loads(payload)) == manifest["counts"]["examples"]
'@ | uv run python -
```
