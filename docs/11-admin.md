# Админка бота

Локальная панель на Python и HTML/CSS/JavaScript, без Node.js и сборки frontend.
Просмотр читает ту же SQLite-базу, что и бот, в режиме `mode=ro`.
Раздел «История Telegram» дополнительно импортирует историю и сохраняет
проверенные оператором наблюдения. Бот может продолжать работать параллельно.

## Запуск в Windows / PowerShell

Из корня репозитория, Python 3.12 или 3.13:

```powershell
uv sync --frozen
$env:ADMIN_PASSWORD = Read-Host "Придумайте пароль админки (минимум 16 символов)"
uv run --frozen python -m pozor.admin
```

`uv` создаёт и обслуживает `.venv` автоматически по `uv.lock`.
Если окружение бота уже синхронизировано, первую команду можно пропустить.
Открыть <http://127.0.0.1:8090> и ввести этот пароль. Для остановки — Ctrl+C.
Пароль можно вместо переменной окружения записать в локальный `.env`:

```dotenv
ADMIN_PASSWORD=замените-на-свой-длинный-случайный-пароль
DATABASE_PATH=./data/pozor.sqlite3
```

Переменная окружения `ADMIN_PASSWORD` имеет приоритет над `.env`.
Настройки бота загружаются обычным `Settings()`: запускайте из каталога,
в котором находится нужный `.env`. Секреты не коммитьте.

Другой файл базы и порт:

```powershell
uv run --frozen python -m pozor.admin --database "C:\path\to\pozor.sqlite3" --port 8095
```

Нужно указать **существующую базу бота с применёнными миграциями**.
Админка не создаёт и не мигрирует базу. Если бот запускается в Docker,
укажите файл SQLite в его bind-mounted каталоге данных на хосте;
не используйте отдельную копию, если хотите видеть текущие изменения.
Для новой установки базу сначала инициализируют штатными командами бота
(см. основной README). Работающая модель или Telegram-соединение самой
админке для просмотра не требуются. Для загрузки истории нужны подключение
аккаунта Telegram и работающая локальная модель.

Если модель запущена через `docker compose`, для админки на Windows укажите
в `.env` адрес `LLM_BASE_URL=http://127.0.0.1:18080` и перезапустите админку.
Порт 8080 используется внутри контейнера; Compose отдельно задаёт боту
`http://llm:8080`. Обновление страницы не применяет изменения настроек Python.

## Linux / macOS

```bash
uv sync --frozen
read -r -s -p 'Пароль админки: ' ADMIN_PASSWORD; echo
export ADMIN_PASSWORD
uv run --frozen python -m pozor.admin --database ./data/pozor.sqlite3
```

Для обычной работы достаточно `uv sync --frozen`; extra `dev` нужен для тестов.
Сервер слушает только `127.0.0.1`. Для базы на другом сервере запускайте
админку рядом с ботом и подключайтесь через SSH-туннель:

```bash
ssh -L 8090:127.0.0.1:8090 user@bot-server
```

После этого локально откройте <http://127.0.0.1:8090>.

## Разделы

- **Портреты.** Выбор чата, поиск по имени, username или ID, страницы по 30
  участников. Один пользователь в двух чатах показан как два отдельных
  контекста. В карточке видны тип наблюдения, цитата, количество эпизодов,
  источники, их авторы, время и ID сообщения. Карточки, исключённые из
  подбора, отмечены отдельно.
- **Чаты.** Локальный реестр: ID, разрешение (`allowed`), включение сбора
  (`enabled`), число участников, срок хранения и время последнего
  сохранённого сообщения. Можно перейти к портретам выбранного чата.
  При добавлении бота в группу событие `my_chat_member` сохраняет ID и название
  в реестре, даже если группа ещё не разрешена. Сбор автоматически не включается:
  используйте «Добавить бота и включить чат» или выберите группу в «Истории Telegram»
  и нажмите «Включить выбранный чат». Выключенные группы доступны для выбора,
  но загрузка истории доступна только после включения сбора.
  Нажмите «Обновить», чтобы перечитать список. Реестр не является сверкой
  актуального членства через Telegram API; выход бота не удаляет запись.
  Если добавление произошло до обновления бота, выберите уже существующую
  группу через «Загрузить мои группы Telegram» и «Добавить бота и включить чат».
- **Промпт прожарки.** Системная инструкция из `pozor.llm.SYSTEM`, путь к файлу,
  SHA-256 и копирование. Пользовательская часть каждого запроса содержит
  отдельный ContextPack; исправляющий повторный запрос может дополнять
  системную инструкцию. После правки `src/pozor/prompts/roast_system.txt`
  перезапустите **оба процесса**, бот и админку: они загружают файл при импорте.

В разделе **История Telegram** доступны QR-вход, загрузка истории и составление
смысловых профилей с проверкой и редактированием перед сохранением. Экспорт JSON
не требуется. Подробности — в [сценарии подключения](12-telegram-profile-pipeline.md).
В разделе **Чаты** нажмите «Загрузить мои группы Telegram», выберите группу
подключённого аккаунта и «Добавить бота и включить чат». Аккаунту нужно право
приглашать участников; админке нужен `BOT_TOKEN`. После подтверждения членства
бота чат разрешается и включается в общей базе. Эти разрешения сохраняются
при перезапуске. `CHAT_ALLOWLIST` больше не используется: доступ хранится в базе.
Если бот уже в группе, повторное приглашение не требуется. Участие можно включить или выключить в разделе **Участники**: выберите чат,
найдите пользователя и нажмите «Включить roast» или «Выключить roast».
Показаны все известные боту участники, включая ещё не включивших участие.
Переключатель действует только в выбранном чате при включённом сборе.
Он управляет прожарками, сбором сообщений и анализом профиля; выключение
завершает активные прожарки цели и отменяет актуальность фоновых результатов.
Участник также может использовать `/roast_on` и `/roast_off`. После `/forget_me`
повторное включение доступно только самому участнику через `/roast_on`. Перед первым запуском обновлённой админки
перезапустите обновлённого бота, чтобы применить миграции базы.

Карточка участника в **Портретах** раскрывается по нажатию: наблюдения,
источники и до 100 последних актуальных собственных сообщений, включая импорт.
Чужие ответы и упоминания показаны отдельно в свёрнутом блоке «Контекст»
с автором и типом связи. Они доступны прожарке с пометкой `third_party`,
но не используются для автоматического смыслового портрета участника.
Сообщения можно увидеть и до составления смыслового профиля.
Системный промпт через панель не изменяется.

Бот при запуске регистрирует меню команд для групп. Пауза между запусками
прожарки для инициатора и цели — 10 секунд. Можно ответить на сообщение
участника текстом `@имя_бота`, `@имя_бота попусти` или вызвать
`@имя_бота @username`. Для вызова тегом выключите privacy mode через BotFather
(и повторно добавьте бота в группу) либо назначьте бота администратором.
При включённом privacy mode используйте `/roast@имя_бота` ответом на сообщение.

## Почему портрет пустой

Показаны только участники, которые дали согласие (`consent=1`), не отказались
от сбора (`opt_out=0`) и не использовали forget-me. Сбор карточек по умолчанию
выключен. Чтобы бот создавал новые карточки, задайте в конфигурации:

```dotenv
PROFILE_CARDS_ENABLED=true
```

Перезапустите бот; чату нужны разрешение, включённый сбор и сообщения участника
с согласием. Автоматические карточки цитат строятся фоновым циклом бота.
Проверенные смысловые наблюдения можно составить в админке независимо от
`PROFILE_CARDS_ENABLED`; их исходные цитаты участвуют в подборе контекста
даже при выключенной автоматической сборке.
Перед показом карточки проверяются оригинальные источники: срок хранения,
принадлежность чату и участнику, действительность импорта, хеш текста.
Просроченные или изменённые источники скрываются даже до запуска cleanup.
Проверки и чтение источников проходят в одной транзакции-снимке SQLite.

## Доступ и проверка

Пароль не передаётся в URL и не сохраняется в browser storage. После входа
используется подписанная HttpOnly / SameSite=Strict cookie сроком восемь часов.
Перезапуск сервера завершает все сессии. Выход удаляет cookie и очищает
загруженные данные интерфейса. Ответы не кешируются. Внешние шрифты,
аналитика и CDN не используются; HTML из имён и цитат не исполняется.
Это локальный HTTP-сервер: для удалённого доступа используйте SSH-туннель.

```powershell
uv run --frozen --extra dev pytest tests/test_admin.py -q --basetemp=.test-tmp/admin
node --check src/pozor/admin_static/app.js
```

Тесты используют синтетическую базу и локальный HTTP-сервер: вход/выход,
авторизация API, разделение чатов, поиск/страницы, неверные запросы,
cross-origin POST, TTL, forget-me, opt-out и изменение исходного текста.
Node.js нужен только для необязательной проверки синтаксиса JS.
