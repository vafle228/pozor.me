# Админка бота

Локальная панель на Python и HTML/CSS/JavaScript, без Node.js, сборки frontend
и дополнительных зависимостей. Админка читает ту же SQLite-базу, что и бот,
в режиме `mode=ro`. Бот может продолжать работать параллельно.

## Запуск в Windows / PowerShell

Из корня репозитория, Python 3.12 или 3.13:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
$env:ADMIN_PASSWORD = Read-Host "Придумайте пароль админки (минимум 16 символов)"
.\.venv\Scripts\python.exe -m pozor.admin
```

Если `.venv` уже установлено для бота, первые две команды не нужны.
Открыть <http://127.0.0.1:8090> и ввести этот пароль. Для остановки — Ctrl+C.
Пароль можно вместо переменной окружения записать в локальный `.env`:

```dotenv
ADMIN_PASSWORD=замените-на-свой-длинный-случайный-пароль
DATABASE_PATH=./data/pozor.sqlite3
```

Переменная окружения `ADMIN_PASSWORD` имеет приоритет над `.env`.
Настройки бота загружаются обычным `Settings()`: запускайте из каталога,
в котором находится нужный `.env`. Секреты не коммитьте.

Другой файл базы и порт:

```powershell
.\.venv\Scripts\python.exe -m pozor.admin --database "C:\path\to\pozor.sqlite3" --port 8095
```

Нужно указать **существующую базу бота с применёнными миграциями**.
Админка не создаёт и не мигрирует базу. Если бот запускается в Docker,
укажите файл SQLite в его bind-mounted каталоге данных на хосте;
не используйте отдельную копию, если хотите видеть текущие изменения.
Для новой установки базу сначала инициализируют штатными командами бота
(см. основной README). Работающая модель или Telegram-соединение самой
админке не требуются.

## Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
read -r -s -p 'Пароль админки: ' ADMIN_PASSWORD; echo
export ADMIN_PASSWORD
.venv/bin/python -m pozor.admin --database ./data/pozor.sqlite3
```

Для обычной работы достаточно `pip install -e .`; extra `dev` нужен для тестов.
Сервер слушает только `127.0.0.1`. Для базы на другом сервере запускайте
админку рядом с ботом и подключайтесь через SSH-туннель:

```bash
ssh -L 8090:127.0.0.1:8090 user@bot-server
```

После этого локально откройте <http://127.0.0.1:8090>.

## Разделы

- **Портреты.** Выбор чата, поиск по имени, username или ID, страницы по 30
  участников. Один пользователь в двух чатах показан как два отдельных
  контекста. В карточке видны тип наблюдения, цитата, количество эпизодов,
  источники, их авторы, время и ID сообщения. Карточки, исключённые из
  подбора, отмечены отдельно.
- **Чаты.** Локальный реестр: ID, разрешение (`allowed`), включение сбора
  (`enabled`), число участников, срок хранения и время последнего
  сохранённого сообщения. Можно перейти к портретам выбранного чата.
  Текущая схема бота не хранит названия и события вступления/выхода бота:
  это не сверка актуального членства через Telegram API.
- **Промпт прожарки.** Системная инструкция из `pozor.llm.SYSTEM`, путь к файлу,
  SHA-256 и копирование. Пользовательская часть каждого запроса содержит
  отдельный ContextPack; исправляющий повторный запрос может дополнять
  системную инструкцию. После правки `src/pozor/prompts/roast_system.txt`
  перезапустите **оба процесса**, бот и админку: они загружают файл при импорте.

В интерфейсе доступны просмотр, поиск и копирование. Изменять настройки чатов,
портреты или промпт через панель нельзя.

## Почему портрет пустой

Показаны только участники, которые дали согласие (`consent=1`), не отказались
от сбора (`opt_out=0`) и не использовали forget-me. Сбор карточек по умолчанию
выключен. Чтобы бот создавал новые карточки, задайте в конфигурации:

```dotenv
PROFILE_CARDS_ENABLED=true
```

Перезапустите бот; чату нужны разрешение, включённый сбор и сообщения участника
с согласием. Профили строятся штатным фоновым циклом бота, не админкой.
Перед показом карточки проверяются оригинальные источники: срок хранения,
принадлежность чату и участнику, действительность импорта, хеш текста.
Просроченные или изменённые источники скрываются даже до запуска cleanup.
Проверки и чтение источников проходят в одной транзакции-снимке SQLite.

## Доступ и проверка

Пароль не передаётся в URL и не сохраняется в browser storage. После входа
используется подписанная HttpOnly / SameSite=Strict cookie сроком восемь часов.
Перезапуск сервера завершает все сессии. Выход удаляет cookie и очищает
загруженные данные интерфейса. Ответы не кешируются. Внешние шрифты,
аналитика и CDN не используются; HTML из имён и цитат не исполняется.
Это локальный HTTP-сервер: для удалённого доступа используйте SSH-туннель.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_admin.py -q --basetemp=.test-tmp/admin
node --check src/pozor/admin_static/app.js
```

Тесты используют синтетическую базу и локальный HTTP-сервер: вход/выход,
авторизация API, разделение чатов, поиск/страницы, неверные запросы,
cross-origin POST, TTL, forget-me, opt-out и изменение исходного текста.
Node.js нужен только для необязательной проверки синтаксиса JS.
