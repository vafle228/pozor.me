# История Telegram и смысловые профили

В админке откройте **История Telegram**. Ручной экспорт переписки не требуется.

## Подключение и работа

1. При первом подключении вставьте API ID и API Hash приложения из
   [my.telegram.org/apps](https://my.telegram.org/apps) в поля панели.
   Это требование Telegram. Альтернатива — `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`
   в `.env`/окружении; они имеют приоритет над локальным файлом панели.
2. Нажмите **Подключить по QR-коду**. В мобильном Telegram откройте
   Настройки → Устройства → Подключить устройство и отсканируйте код.
   При необходимости введите облачный пароль. Пароль не сохраняется.
3. Выберите группу, период в UTC (до года, конечная дата не включается)
   и до десяти участников. Показаны включённые группы бота, доступные аккаунту,
   и участники, которые уже дали `/roast_on`. Импорт не выдаёт согласие за них.
4. Нажмите **Загрузить историю и составить профили**. Видны этап и прогресс,
   доступна отмена. Одна админка исполняет одну такую задачу одновременно.
5. Проверьте цитаты, снимите лишние галочки, отредактируйте текст и сохраните
   выбранное. Сохранение заменяет предыдущие проверенные наблюдения участника
   в этой группе. Обычные автоматические карточки цитат остаются отдельными.

Кнопка **Отключить аккаунт** отменяет задачу, отзывает Telegram-сессию,
удаляет локальные файлы подключения и очищает черновики. Импортированные
цитаты и сохранённые профили остаются в базе. Сессию также можно отозвать
в Telegram → Устройства. Перезапуск админки сохраняет авторизацию.

## Где хранятся данные

Сессия — `<каталог базы>/telegram/account.session`, введённые через панель
данные приложения — `application.json` рядом. Это секретные локальные файлы,
их нельзя публиковать или копировать в общие каталоги. На Unix каталог/файл
приложения создаются с правами 0700/0600; в Windows используются ACL каталога
данных. Сессия технически даёт доступ аккаунта Telegram. Приложение использует
её для чтения истории, без отправки сообщений от имени пользователя.

Группы сопоставляются по точному Telegram peer ID, без сравнения имён.
Сохраняются только текстовые сообщения выбранных авторов, без медиа, соседей
и чужих реплик. Импорт использует существующие preview/apply и privacy guards.
Временные JSON/manifest удаляются после попытки apply. Цитаты остаются в SQLite
на срок хранения импорта (по умолчанию 90 дней после apply).

Повторный импорт не дублирует сообщения; конфликт редакций завершает задачу
ошибкой. Отмена, отключение и ошибка модели не откатывают завершённый импорт.

Черновики хранятся в памяти до 30 минут и не переживают перезапуск. Перед показом
и сохранением проверяются согласие, epoch, хеши, происхождение и TTL источников.
Forget/rollback/edit/opt-out не позволяют сохранить устаревший черновик.
Сохранённые наблюдения используют `profile_cards`/`card_evidence` и существующие
invalidation triggers; новая миграция не нужна.

## Ограничения анализа

- До 10 000 просмотренных сообщений за выбранный период в группе.
  При превышении выберите меньший период; частичный архив не активируется.
- До 300 последних доступных собственных сообщений участника внутри периода,
  по 15 сообщений на запрос. Модель видит первые 2000 символов каждого текста;
  оператору для проверки показывается полный источник.
- До 30 наблюдений по 240 символов, каждое с 1–3 цитатами. Проверка ID подтверждает
  происхождение цитат, но не гарантирует правильность смыслового вывода модели.
  Поэтому перед сохранением нужна проверка оператором.
- Бот использует **исходные цитаты** сохранённых наблюдений при подборе контекста,
  в том числе при `PROFILE_CARDS_ENABLED=false`. Пересказ модели не становится
  новой цитатой или фактом в prompt. После обновления кода перезапустите бот.
- Автоматическое обновление смысловых наблюдений по новым сообщениям пока
  не включено: повторный анализ запускается из панели.
- Админка не управляет внутренней очередью модели в отдельном процессе бота.
  Анализ может конкурировать за GPU; запускайте его вне активных прожарок.

## Запуск и проверка

Обновите зависимости через `uv sync --frozen` и запустите админку по
[основной инструкции](11-admin.md). Модель должна быть доступна по `LLM_BASE_URL`.
Для текущего Docker Compose адрес с Windows-хоста — `http://127.0.0.1:18080`,
из контейнера — `http://llm:8080`.

```powershell
uv run --frozen --extra dev pytest tests/test_admin.py tests/test_profiles_privacy.py tests/test_profile_pipeline.py -q
node --check src/pozor/admin_static/pipeline.js
```

Offline-тесты подменяют Telegram и модель. Проверены импорт → анализ → проверка
→ сохранение → показ/подбор цитат, согласие и границы групп, изменение источников,
TTL, forget, отмена, QR/2FA и HTTP authentication/origin/content-type.
Реальный вход в Telegram требует QR/2FA владельца аккаунта.
