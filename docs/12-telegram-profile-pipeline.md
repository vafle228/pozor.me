# История Telegram и смысловые профили

В админке v0.2 откройте **История Telegram**. Здесь можно загрузить историю
через подключённый Telegram-аккаунт и подготовить наблюдения о выбранных участниках.
В v0.2 для импорта требуется действующее согласие в выбранной группе.
Участие по умолчанию во включённых группах запланировано для следующей версии.

## Подключение и работа

1. Если реквизиты ещё не настроены, вставьте в поля панели API ID и API Hash
   приложения с [my.telegram.org/apps](https://my.telegram.org/apps). Сохранённые
   в панели реквизиты имеют приоритет. При их отсутствии используются
   `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из настроек установки.
2. Нажмите **Подключить по QR-коду**. В мобильном Telegram откройте
   Настройки → Устройства → Подключить устройство и отсканируйте код.
   При необходимости введите облачный пароль. Пароль не сохраняется.
3. Выберите группу из числа известных боту и доступных аккаунту. Если сбор
   выключен, в панели есть кнопка **Включить выбранный чат**. Для группы,
   которой нет в списке, используйте раздел **Чаты**. При добавлении группы
   приложение проверяет членство бота и при необходимости приглашает его через
   подключённый аккаунт. Для приглашения у аккаунта должно быть соответствующее право.
   Укажите период в UTC (до 366 дней, конечная дата не включается) и отметьте
   от одного до десяти участников с действующим согласием в этой группе.
4. Нажмите **Загрузить историю и составить профили**. Видны этап и прогресс,
   доступна отмена. Панель выполняет одну задачу загрузки за раз.
5. Проверьте цитаты, снимите лишние галочки, отредактируйте текст и сохраните
   выбранное. Сохранение заменяет предыдущие проверенные наблюдения участника
   в этой группе. Автоматические наблюдения хранятся отдельно от проверенных.

Кнопка **Отключить аккаунт** отменяет задачу и очищает черновики. После
успешного выхода из Telegram приложение удаляет файлы сессии и сохранённые
панелью реквизиты. Импортированные цитаты и сохранённые профили остаются
в базе. Сессию также можно отозвать в Telegram → Устройства. При обычном
перезапуске приложения сохранённая сессия используется повторно.

## Где хранятся данные

Сессия хранится в `<каталог базы>/telegram/account.session`, а введённые
через панель реквизиты приложения — в `<каталог базы>/secrets.local.json`.
В прежней версии реквизиты лежали в `telegram/application.json`. При чтении
старой установки без нового файла приложение переносит реквизиты и удаляет
старый файл. Сессия даёт доступ к аккаунту Telegram. Храните её, реквизиты и
резервные копии в закрытом каталоге. На Unix приложение устанавливает права
`0700` для каталога сессии и `0600` для файла реквизитов. В Windows для них
применяются ACL текущего пользователя и SYSTEM.

Группы сопоставляются по Telegram peer ID. В пределах выбранного периода
загрузчик может получить исходное сообщение, на которое ответил участник,
и соседние сообщения с ID на единицу меньше и больше. Для соседних сообщений
также действует окно в пять минут. Импорт отбирает контекст,
сохраняет исходное авторство и отделяет чужие реплики от собственных цитат
участника. Медиафайлы не загружаются.

Для каждого участника приложение составляет предварительную выборку и манифест,
затем повторно проверяет права группы, согласие и источник при записи в SQLite.
Временные файлы выгрузки и манифеста удаляются после попытки импорта.
По умолчанию срок использования импортированных цитат — 90 дней с момента
активации импорта.

Повторный импорт тех же сообщений использует существующие записи. Если данные
одного сообщения расходятся с сохранённой версией, задача завершается ошибкой.
При отмене, отключении или ошибке модели уже активированные партии сохраняются.

Черновик доступен для проверки и сохранения в течение 30 минут. Он хранится
в памяти процесса. При показе и перед записью приложение проверяет согласие,
версию данных участника, хеши и право использовать каждый источник с учётом
срока хранения. После изменения источника, отката импорта, отзыва согласия или
`/forget_me` устаревший черновик сохранить нельзя. Наблюдения лежат в
`profile_items`, ссылки на цитаты и их хеши — в `profile_item_sources`.

## Ограничения анализа

- Лимит загрузки — 10 000 сообщений **на каждого выбранного участника** за
  указанный период. При превышении задача завершается до импорта. Сократите период.
- Для анализа из последних 3000 доступных собственных сообщений участника
  внутри периода отбираются до 300 содержательных. Команды и распознанные
  обращения к боту пропускаются. Модель получает до 15 сообщений за запрос
  и первые 2000 символов каждого текста. Оператор видит цитаты целиком.
- В черновике до 30 наблюдений длиной до 240 символов, каждое с 1–3 цитатами.
  Перед сохранением проверьте по цитатам и авторство, и смысл вывода модели.
- При подборе контекста бот учитывает исходные цитаты сохранённых наблюдений
  даже при `PROFILE_CARDS_ENABLED=false`. Этот флаг управляет прежними карточками
  цитат. Автоматическое досье передаётся как пересказ со ссылками на исходные
  сообщения после проверки их хешей, авторства и срока хранения.
- Автоматическое составление включено по умолчанию (`SEMANTIC_PROFILES_ENABLED=true`).
  В режиме `serve` бот обходит участников с согласием, затем ждёт 30 секунд
  до следующего обхода. Первый анализ запускается от 10 подходящих собственных
  сообщений. При изменении выборки профиль обновляется после 20 новых подходящих
  сообщений или по истечении 10 минут с предыдущего обновления. Между попытками
  проходит не менее минуты. Статус и прогресс видны в «Портретах» после
  «Обновить». Автоматические наблюдения помечены отдельно. Обновление учитывает
  прежние наблюдения с актуальными источниками, сохраняет проверенные оператором
  записи и исключения. Для досье используются до 60 наблюдений, длина пересказа
  ограничена 2000 символами. В «Портретах» можно раскрыть источники досье и
  проверить, верно ли модель поняла смысл цитаты.
- В режиме `serve` бот, админка и автоматический анализ используют одну
  очередь модели. Интерактивный запрос прерывает текущий фоновый запрос.
  Анализ может повторить прерванную порцию, сохранив уже обработанные.

## Запуск и проверка

После `uv sync --frozen` запустите `uv run pozor serve` для бота и панели
или `uv run pozor admin` для работы только с панелью. При работающем `serve`
откройте его панель. Блокировка допускает один процесс `serve` или `admin`
на БД. Настройка описана в [руководстве v0.2](13-v02-runbook.md).
Модель должна быть доступна по `LLM_BASE_URL`.
Для текущего Docker Compose адрес с Windows-хоста — `http://127.0.0.1:18080`,
из контейнера — `http://llm:8080`.

```powershell
uv run --frozen pytest tests/test_admin.py tests/test_profiles_privacy.py tests/test_profile_pipeline.py tests/test_auto_profiles.py -q
node --check src/pozor/admin_static/pipeline.js
```

Эти тесты используют временную БД и подменяют Telegram и модель. Они проверяют
импорт, анализ, сохранение и подбор цитат, согласие и границы групп, изменение
источников, истечение срока хранения, отмену, QR/2FA и обработку запросов к панели.
