# T4: inference и retrieval

T4 — самостоятельный слой; подключение к `runtime.py` и Telegram выполнено в [T5](07-t5-delivery.md). Карточки, extractor/watermarks и benchmark качества принадлежат T6. Queue поддерживает background factories, но не подменяет extractor фиктивными карточками.

## Границы и API для T5

1. Применить миграции, создать один `LlamaClient(settings)` на процесс. На старте `await client.check(deadline)` проверяет `/health`, `/v1/models`, один `/slots` и `n_ctx >= CONTEXT_SIZE`. Отказ означает недоступность генерации; ingestion/stop должны продолжать работать. Не открывать сессию, пока проверка не прошла.
2. Один `Generator(client)` сохраняет circuit breaker: три ошибки подряд, пауза 30 секунд. Один `InferenceQueue(client.wait_idle)` обслуживает всю GPU, capacity 8 interactive + 16 background. `key="session:<id>"` — максимум одна pending/in-flight работа сессии; `key="target:<chat>:<target>"` для background coalescing. `QueueBusy` преобразовать в «занят», с ограничением повторных уведомлений на чат в T5.
3. `retrieve(path, chat_id=..., thread_id=..., target_id=..., trigger_id=..., hint=..., target_label=..., weights=settings.retrieval_weights)` возвращает `ContextPack` и epoch из одной SQLite snapshot. Синхронное DB-чтение вызвать через `asyncio.to_thread`, не держать транзакцию во время HTTP. Recent — до 20 live сообщений с target entitlement только текущей темы; исторические цитаты могут относиться к другим темам той же группы. Imported/manual доступны только через активный batch данного target. Карточек до T6 нет.
4. Добавить только ходы этой сессии в `session_turns`. Они используются для repetition checks, не становятся evidence профиля. Проверить revision/epoch и consent до enqueue. Сформировать абсолютный monotonic deadline **до** retrieval/очереди: `loop.time() + settings.generation_deadline_seconds` (по умолчанию 8 секунд).
5. `await queue.submit(key=..., chat_id=..., deadline=..., factory=lambda d: generator.generate(pack, d))`. Результат `GenerationResult`: validated roast либо явный neutral fallback, token_count полного prompt и context_hash. `evidence_ids` относятся только к реально упакованным материалам. `token_count` — metadata результата, а не поле, меняющее сериализацию ContextPack при подсчёте самого себя.
6. Отменять через `queue.cancel(key)` при stop/edit/rollback/замене revision, обрабатывать `CancelledError`, `TimeoutError`, `QueueBusy`, `InferenceError`. Отмена HTTP не доказывает освобождение GPU: перед следующей factory очередь опрашивает серверный `/slots` до idle, внутри исходного deadline. Если сервер не освободился, новая completion не стартует. Background job ограничен пятью секундами, interactive отменяет выполняющийся background HTTP. Реальное освобождение GPU нужно дополнительно проверить операторским smoke; offline тест проверяет протокол отмены/ожидания через MockTransport.
7. Перед outbox и перед send повторно проверять session/revision/epoch/turn/deadline/consent. Это работа T5; `context_hash` и успешная валидация не дают права на отправку. Передавать текст в Telegram с `parse_mode=None`. При shutdown `await queue.aclose()`, затем закрыть HTTP client.

## Retrieval и бюджет

Четыре списка до 40 кандидатов: scoped FTS rank ASC (BM25), recent self, mentions/replies, активное досье. Safe quoted MATCH: не более 12 terms, словарь v1 reddit/реддит и game/игра. RRF weights по умолчанию 1/.8/.5/.6, k=60; порядок при равном score — ID. Сохраняются автор, relation, attribution, source keys, hash и policy version. Third-party/manual не становятся self. Дубликаты удаляются по ID и нормализованному тексту.

Диверсификация пока консервативно группирует исторические сообщения по thread (экспорт без thread — одна группа), ручные заметки — dossier. Это не semantic topic extraction и не карточки T6. Настройки `HISTORICAL_TOKEN_BUDGET=1200`, `PER_TOPIC_LIMIT=2`, `RETRIEVAL_WEIGHTS=[1.0,0.8,0.5,0.6]` доступны через Settings. Недавняя reply chain имеет отдельный бюджет 900, session memory 600. System и trigger не обрезаются. При переполнении полного prompt сначала удаляется низкоранговая история, затем старые ходы, затем старый recent context; если обязательная часть не влезла, completion не вызывается.

Каждый evidence считается вместе с JSON metadata реальным `/tokenize`. Полный prompt считается через `/apply-template` + `/tokenize` с non-thinking kwargs, с резервом 512 и output cap 180. Retry тоже пересчитывается; максимум две completion, второй только при invalid output, внутри того же deadline. Network errors не ретраятся. Никаких len(text)/4 и скрытых LLM reranker/judge.

`0006_retrieval.sql` добавляет nullable `reply_source_id`. Новые live/экспортные сообщения сохраняют его; старые данные не восстанавливаются по догадке. Parent ищется только в том же source namespace и target scope. Недоступный parent маркируется missing. Поле available относится к snapshot retrieval: бюджет может исключить parent из окончательного pack, и модель не должна реконструировать пропущенный текст.

## Проверки и эксплуатационные ограничения

`tests/test_intelligence.py` использует настоящий httpx adapter с `MockTransport`, синтетические SQLite fixtures и реальный asyncio scheduler. Сеть не нужна. Отдельные import/ingestion tests проверяют сохранение reply ID и end-to-end import → scoped retrieval → rollback. SQL-миграции проверяются на чистой БД и при upgrade с прежних версий.

Prompt хранится в package resource `pozor/prompts/roast_system.txt`. Строгая Pydantic schema запрещает лишние поля, в том числе выдуманное поле author. Validator проверяет разрешённые IDs, длины, дубли, think blocks, ссылки/телефоны/mentions, длинные цитаты и repetition. Это не семантический детектор всех ложных утверждений об авторстве или запрещённых тем: корректный ID ещё не гарантирует правдивую формулировку. Нужны human eval T6; raw invalid output никогда не возвращается для публикации.

`pozor llm smoke` использует только синтетическую вводную и уже имеющийся сервер. `enable_thinking=false` передаётся в template и completion; непустой reasoning_content, reasoning tokens и think blocks отклоняются. Отсутствие этих полей не доказывает отсутствие скрытых вычислений. `deployment-lock.json` явно unverified; SHA/revision/filename/build/GPU/backend/latency не выдуманы. Оператор должен закрепить реальный artifact и llama.cpp build, сверить prompt template, GPU offload, slot release после отмены, hidden thinking и latency. Автоскачивания весов нет.

Контракт адаптера сверялся с [официальным llama.cpp server API](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). Конкретная сборка ещё не проверена; несовместимый `/slots` или tokenizer завершается отказом, без приблизительного подсчёта и без параллельной completion.
