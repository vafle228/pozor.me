# Pozor.me v0.2: запуск и обновление

## Обновление существующей установки

Остановите прежний бот и отдельную админку. Новый `serve` владеет обоими; параллельный запуск на той же БД блокируется файловой блокировкой.

Перед миграцией сохраните проверенную SQLite-копию:

```powershell
uv sync --frozen
uv run pozor db backup --directory data/backups --before-upgrade
uv run pozor db migrate
uv run pozor config where
uv run pozor doctor
uv run pozor serve
```

`--before-upgrade` принимает только известный, проверенный по checksum префикс миграций. Не копируйте работающий SQLite-файл обычным файловым копированием: актуальные страницы могут быть в WAL. Миграции 0013–0018 создают права на источники, настройки, журнал, оценки и `profile_items`. Переносятся доступные карточки v2–v4 с действующими источниками. Старые извлекаемые карточки v1 отбрасываются. Миграции вперёд необратимы: откат к старому коду требует отдельного снимка до обновления и соответствующей ему версии приложения.

Сохранённый `data/telegram/application.json` автоматически переносится в `data/secrets.local.json`. Сохранённые реквизиты имеют приоритет над env. Сессия Telegram остаётся в прежнем каталоге. Новая версия не восстанавливает участие после `/forget_me`.

## Конфигурация

`.env` ищется в `POZOR_HOME`, иначе рядом с `pyproject.toml`; текущий рабочий каталог не определяет расположение конфигурации. В установленном wheel без проекта задайте `POZOR_HOME`. `POZOR_DATA_DIR` задаёт каталог данных, `DATABASE_PATH` — явное исключение для пути SQLite.

Обязательные секреты для `serve`: `BOT_TOKEN`, `ADMIN_PASSWORD` (от 16 символов). При запуске модели через Compose с Windows-хоста используйте `LLM_BASE_URL=http://127.0.0.1:18080`. Внутри Compose `app` использует `http://llm:8080`.

```powershell
uv run pozor config show
uv run pozor serve --set temperature=0.95
uv run pozor config set temperature 0.95
uv run pozor config set generation_deadline_seconds 30
uv run pozor config history
uv run pozor config rollback 1
uv run pozor config reset temperature
uv run pozor config template --check
```

Bootstrap-параметры меняются перезапуском. Runtime-параметры берутся из снимка на запрос: CLI overrides сервиса → БД → env → `pozor.toml` → default. Источник виден в `config show` и админке. `config history` содержит только runtime-настройки; секреты туда не записываются. Для override через собственную интеграцию передайте `SettingsService(seed, cli={...})`.

Смена `ADMIN_PASSWORD` в принадлежащем установке `.env` действует без перезапуска и инвалидирует старые cookies. Переменная процесса имеет приоритет над файлом: для её смены перезапустите процесс с новым окружением. Админка не раскрывает и не редактирует значения секретов.

В Windows `private_write` применяет ACL текущего пользователя и SYSTEM к секретным файлам; каталог Telegram-сессии также ограничивается через ACL. Для всего каталога данных и бэкапов установите отдельный приватный ACL либо используйте Linux-том Docker/WSL. Не помещайте данные в общий каталог без ограничения доступа.

## Админка и Docker

`uv run pozor serve` запускает бот, админку и фоновые задачи в одном процессе. `uv run pozor admin` — отдельный режим только админки. Оба используют один контейнер зависимостей и очередь; одновременно на одной БД не запускаются.

```powershell
docker compose build
docker compose up -d llm app
```

Панель: `http://127.0.0.1:8090`. Веб-сервер внутри контейнера слушает `0.0.0.0`; публикация Compose ограничена loopback хоста. Linux-пользователь образа — UID/GID 1000; bind mount должен разрешать ему запись. В образ не включаются `.env`, переписки, БД или Telethon-сессия. `/healthz` проверяет БД, схему, модель и очередь. Логи запросов админки отключены.

Для HTTPS используйте свой reverse proxy, затем `ADMIN_SECURE_COOKIE=true`. Сервер проверяет Origin и CSRF на изменяющих запросах, cookie — HttpOnly/SameSite=Strict, после пяти неверных входов по умолчанию действует окно 10 минут. Не запускайте отдельный `admin` поверх работающего `serve`.

## Юмор и согласие

`/roast_on` соответствует L2. `/roast_on 1`, `2`, `3` задаёт максимум участника. Уровень — минимум глобального потолка, потолка чата, запроса и согласия цели; «мягко» снижает его до L1. Потолок чата меняется в пульте, раздел «Чаты»; API `/api/chats/level` требует авторизацию и CSRF. `/stop`, `/finish`, `/roast_off`, `/forget_me` сохраняют прежние ограничения и очистку.

V2 создаёт ровно пять черновиков с разными механизмами, фильтрует их и передаёт судье при temperature 0. Разрешены только зацепки с точной собственной цитатой и текущим источником. Список повторов хранится семь дней; новые сообщения не превращают чужие слова в факты о цели. Имя подставляет приложение. Обычный диалог использует отдельную схему `{text}`.

Стандартный дедлайн — 30 секунд: на имеющемся GPU пять черновиков и судья заняли 21,7–24,5 секунды. Это небольшой smoke, а не p95 или гарантия скорости. `max_output_tokens=600`, temperature 0.9, top_p 0.95, min_p 0.05, presence_penalty 0.4. Настройки доступны в пульте.

Кнопки 🔥 / 😐 / 💩 доступны для отправленной шутки в исходном чате и сообщении; оценка одного участника заменяет его предыдущую. Две положительные оценки дают пример для следующего запроса этой цели. Выключение согласия, удаление/редактирование источников и `/forget_me` инвалидируют приватные копии в журнале. Обычная очистка удаляет журнал старше семи дней.

## Проверка качества

```powershell
uv run poe check
uv run pozor eval humor --check
uv run pozor eval retrieval
uv run pozor eval humor --dataset tests/fixtures/humor_synthetic.jsonl --variant A --variant B
# Следующая команда ЯВНО отправляет обезличенные пары в служебную группу:
uv run pozor eval publish data/eval/humor.json -1001234567890
uv run pozor eval results -1001234567890 --variant B
```

A — старый генератор, B — V2 на том же сервере. Порядок ответа в паре перемешивается; кнопки A/B/«Равны» не показывают вариант. Приёмка: минимум 40 оценённых пар, win-rate ≥60%; равенства не считаются победами. Результаты публикуются только явной командой оператора, в разрешённый чат.

Штатный набор из 60 ситуаций — синтетический. Для реального золотого набора оператор должен подготовить обезличенные ситуации и контекст; экспорт живых переписок в Git автоматически не выполняется. Пример записи: `{"id":1,"synthetic":true,"trigger":"опять проспал созвон"}`. Проверка `--check` не запускает модель и не измеряет смешность.

## Бэкапы и восстановление

`pozor db backup` создаёт согласованный снимок, проверяет схему, foreign keys, FTS и integrity, затем ротирует только собственные старые снимки. `pozor db restore --source ... --destination ...` восстанавливает в новый путь и отменяет потенциально отправленные/ожидающие старые ответы.

Расписание запускайте внешним cron/Task Scheduler, как в документах T7. При необходимости шифруйте снимок `age` перед переносом; ключ расшифрования храните отдельно. Раз в месяц выполните восстановление в отдельный приватный каталог и проверку `status`. Само расписание и управление ключами не устанавливаются PR: это настройки владельца сервера. Файл `secrets.local.json` и сессия Telegram находятся отдельно от SQLite и не включаются в DB backup; их защищают отдельным приватным процессом восстановления.
