# Локальное слепое сравнение юмора

В HUM-01 единица оценки — целый групповой диалог и два ответа бота на его последний момент. Оценщик решает, стоило ли боту вступать, затем читает оба текста, отмечает свою реакцию на каждый и выбирает лучший ответ для разговора. Одинаково хорошие и одинаково слабые варианты могут получить ничью. Приёмка требует минимум 40 оценённых человеком пар и минимум 60% побед кандидата среди всех оценённых пар, включая ничьи.

## Отложенный набор

Для финального сравнения TRAIN-01 20 ноября 2026 года подготовлены 40 новых синтетических русскоязычных диалогов. В них 163 сообщения и минимум три собеседника в каждом. Среди сцен есть и бытовые разговоры, которые уместно оставить без вмешательства. Файл `data/hum-01/holdout-20261120/dialogs.jsonl` и его manifest хранятся локально вне Git. SHA-256 файла — `a697da6ae95e24c8b613abd2afedce87c2d507a1658c1e8c339935e2b12926e7`. У каждого диалога есть `id` и упорядоченный `context` из объектов с полями `author` и `text`.

Диалоги целиком отложены для финального сравнения зафиксированных базовых и дообученных весов. Для обучения, калибровки, выбора промпта, подбора checkpoint и сравнения механик MIG-04 используйте другие сцены. Временные модельные или демонстрационные голоса в итог не входят. Набор даёт отдельный результат на синтетических ситуациях. Для вывода о реальной беседе требуется отдельно разрешённая выборка.

## Подготовка пары серий

До генерации зафиксируйте сравниваемые версии, хеши весов, режим генерации, промпты, параметры и обработку ошибок в локальном протоколе прогона. Для сравнения весов подайте обеим версиям один и тот же полный контекст и используйте одинаковый runtime. В каждой сцене запросите один итоговый текст от каждой версии, включая штатный fallback. При техническом сбое сохраните ошибку и доведите ту же серию до полноты по заранее определённому правилу. Исключение неудачных текстов и повторный отбор удачных меняют смысл сравнения.

Для `pack` подготовьте два приватных UTF-8 JSON-файла. `variant` идентифицирует зафиксированный запуск, `suite_sha256` равен SHA-256 исходных байтов полного JSONL, в `responses` находится по одному тексту на каждый `id`. Пример структуры на условном диалоге:

```json
{
  "variant": "имя запуска из протокола",
  "suite_sha256": "хеш файла диалогов",
  "responses": {"demo-01": "Текст ответа бота"}
}
```

Из корня репозитория оператор выполняет

```powershell
$batch = 'data/hum-01/holdout-20261120'
uv run python ops/humor_blind.py pack "$batch/dialogs.jsonl" "$batch/base.json" "$batch/tuned.json" "$batch/final"
```

Первый файл ответов — базовая серия, второй — кандидат. Команда проверяет хеш и полный набор ID, случайно меняет порядок диалогов и уравновешивает позиции вариантов слева и справа. Новый каталог `final/review` содержит только диалоги и тексты A и B. Ключ позиций, исходные ID и названия сравниваемых запусков остаются у оператора в `final/key`. Для оценщика нужен только каталог `review`, запускать оценку можно и с его отдельной копией. Инструмент работает без Telegram и базы бота.

Каждая последовательность реплик с теми же авторами учитывается один раз. Повтор под другим ID нужно убрать до сборки. При полном совпадении показанных ответов инструмент присваивает паре ничью. Оценщик по-прежнему отмечает уместность и реакцию на каждый вариант. Это правило подсчёта применяется и к ранее сохранённым голосам.

## Оценка

```powershell
uv run python ops/humor_blind.py review "$batch/final/review"
```

На вопрос о моменте ответа введите `да`, `нет` или `?`. После появления вариантов отметьте по отдельности, насколько рассмешили A и B. Значение `0` означает «не смешно», `1` — «улыбнуло», `2` — «рассмешило». Затем введите латинскую `A`, `B` или `=` для ничьей. Выбор конкретного текста сохраняется и в тех сценах, где вы предпочли бы молчание.

Команда сохраняет каждую завершённую пару. Можно прерваться сочетанием Ctrl+C и продолжить с той же папкой. Один бланк предназначен для одного независимого оценщика. Если оценщик получил копию папки, верните сохранённые `vote-*.json` в исходный `final/review`.

```powershell
uv run python ops/humor_blind.py score "$batch/final"
```

До заполнения всего бланка команда сообщает только число готовых пар. После завершения она сверяет хеш бланка с ключом и голосами и выдаёт победы, поражения, ничьи, долю побед и прохождение порога. При 40 парах нужны как минимум 24 победы. Отдельные поля показывают реакции на каждый вариант и число сцен, в которых человек предпочёл бы вступить, промолчать или затруднился выбрать. Эти оценки момента помогают разбирать уместность. Точность выбора момента самим ботом измеряется отдельно в MIG-06.
