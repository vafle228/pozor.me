**pozor.me** — проект локального Telegram-бота для контекстной прожарки в группе. Бот должен находить относящиеся к разговору реплики и отвечать коротко и остроумно, опираясь на подтверждённые сообщения и выбранную историю человека.

> **Статус:** T0–T5 реализованы с offline acceptance. T6 добавляет цитатные карточки, удаление и offline eval; пакет **не закрыт** до ручной оценки качества и замеров локальной модели. `pozor run` подключает реальные Telegram Bot API и локальный llama.cpp. Реальные Telegram/GPU smoke не проводились. [Статус и передача T6](docs/08-t6-profiles-privacy-eval.md).

## Задача и границы

Первая версия рассчитана на личный запуск в нескольких небольших группах. Она должна принимать новые сообщения только из разрешённых чатов, поддерживать добровольное участие, импорт выбранной истории и генерацию ответа локальной языковой моделью. Владелец выбирает импортируемые данные; само добавление истории не включает участие в прожарке.

Прожарка ограничена короткими ответами и явными правилами остановки. Бот не должен превращать чужие шутки или заметки оператора в факты о человеке. Адреса и контакты, здоровье, сексуальная жизнь, защищённые характеристики, угрозы и выдуманные серьёзные обвинения исключаются из тем для шуток. Молчание завершает сессию и не считается признанием поражения.

В V1 не входят голосовые сообщения, OCR, распознавание изображений, веб-поиск по людям, userbot, дообучение модели, векторная база и веб-интерфейс. Для старой истории Telegram нужен экспорт, выбранный оператором: Bot API не предоставляет историю прошлых сообщений группы.

## Планируемый стек

- Python 3.12+ и aiogram 3.
- SQLite с WAL и FTS5 на локальном диске.
- Локальный llama.cpp и Qwen3-8B Q4_K_M; thinking отключён.
- Один процесс приложения и один процесс inference; без Redis и фоновых микросервисов в V1.
- Ориентир по оборудованию — одна GPU с 16 ГБ VRAM. CUDA — основной вариант для NVIDIA; Vulkan требует отдельной проверки. Скорость заранее не обещается и должна быть измерена на целевом оборудовании.

Python-зависимости закреплены в `uv.lock`. `deployment-lock.json` отмечает модель как непроверенный baseline: build/revision/artifact/SHA и замеры нужно заполнить после реального smoke. Реальные переписки, токены и веса моделей не добавляются в репозиторий.

## Проверка эталонного кода

Для уже реализованных эталонных алгоритмов достаточно Python; сторонние пакеты не нужны:

```powershell
python -m unittest discover -s tests -v
```

Эта команда проверяет reference-алгоритмы. Полный offline suite приложения: `uv run --extra dev --extra imports pytest -q` (в Windows sandbox может потребоваться разрешение на локальный socketpair asyncio).

## CLI и локальная диагностика

Установить закреплённые зависимости и посмотреть доступные команды:

```powershell
uv sync --frozen
uv run pozor --help
```

`uv run pozor doctor` проверяет конфигурацию, поддержку FTS5 в SQLite, доступность каталога базы данных и наличие `BOT_TOKEN`. Команда не обращается к сети и не выводит значение токена. `uv run pozor db migrate` применяет checksum-защищённые миграции. `uv run pozor run` запускает Telegram long polling и требует токен; для offline-проверок эта команда не нужна.

`uv run pozor llm smoke` — отдельная opt-in проверка уже запущенного локального llama.cpp: health, alias модели, один slot, размер контекста, tokenizer и structured non-thinking completion на синтетической вводной. Веса не скачивает, в Telegram не пишет. Порядок подключения T4 к T5 описан в [контракте T4](docs/06-t4-inference.md).

## Название и команды

T6: `/forget_me` удаляет данные участника в текущей группе и запрещает восстановление
импортом до явного `/roast_on`. `/roast_off` только выключает участие. Локально:
`pozor profile show --chat <id> --target <id>`, `pozor db cleanup`,
`pozor benchmark --suite tests/fixtures/eval.jsonl --output reports/t6-benchmark.json`.
Benchmark по умолчанию offline; `--live --repeat 3` явно включает уже запущенный
локальный llama.cpp на синтетических данных. Telegram не используется.
Карточки включаются через `PROFILE_CARDS_ENABLED=true`; direct retrieval работает
при выключенных карточках. Фоновая сборка использует настоящий tokenizer llama.cpp,
но сохраняет только точные цитаты, без LLM-пересказа.

`pozor.me` — название проекта, а не допустимый username Telegram. Для регистрации понадобится свободное имя вида `@pozor_me_bot`, созданное через BotFather; такое имя в документации приведено как пример.

Команды `/enable_chat`, `/disable_chat`, `/help`, `/whois`, `/roast_on`, `/roast_off`, `/roast`, `/stop` и `/finish` реализованы. `/roast` открывает ограниченную сессию при доступном inference; T5 генерирует панч и продолжает только по прямому обращению target. Импорт использует локальные JSON-файлы, сохраняет provenance и не запускает импортированные команды. Поведение и разрешения описаны в [дизайне](docs/01-design.md), доставка и ограничения — в [контракте T5](docs/07-t5-delivery.md).
