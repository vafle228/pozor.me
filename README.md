![Аниме-баннер pozor.me](.github/readme-banner.png)

**pozor.me** — проект локального Telegram-бота для контекстной прожарки в группе. Бот должен находить относящиеся к разговору реплики и отвечать коротко и остроумно, опираясь на подтверждённые сообщения и выбранную историю человека.

В **v0.2** для прожарки модель готовит пять кандидатов за попытку, а судья выбирает шутку из прошедших фильтры. Движок использует зацепки из собственных цитат и учитывает недавние повторы. Участник выбирает уровень согласия. Бот и админка используют общую очередь модели.

## Запуск v0.2 на Windows

Для новой установки нужны Python 3.12, `uv` и локальный сервер llama.cpp. Из корня проекта установите зависимости и проверьте путь к файлу конфигурации.

```powershell
uv sync --frozen
uv run pozor config where
```

Если по указанному пути ещё нет `.env`, скопируйте туда `.env.example` под именем `.env`. Укажите токен бота `BOT_TOKEN`, пароль панели `ADMIN_PASSWORD` длиной от 16 символов и адрес модели `LLM_BASE_URL`. Если модель запущена через Compose, а приложение работает на Windows, адрес модели — `http://127.0.0.1:18080`.

При обновлении существующей установки сначала остановите прежние процессы и сделайте резервную копию командой `uv run pozor db backup --directory data/backups --before-upgrade`. Затем примените миграции, проверьте настройки и запустите приложение.

```powershell
uv run pozor db migrate
uv run pozor doctor
uv run pozor serve
```

`serve` запускает бот, админку и фоновые задачи в одном процессе. Панель по умолчанию доступна по адресу `http://127.0.0.1:8090`. Для работы только с панелью запустите `uv run pozor admin` при остановленном `serve`. Одна база допускает один такой процесс.

[Запуск, обновление и оценка качества v0.2](docs/13-v02-runbook.md) · [Отчёт о переработке](reports/refactoring-2026-11-01.md) · [План этапов](docs/12-refactoring.md).

Локальные проверки проекта запускает `uv run poe check`. Для человеческой приёмки юмора нужны минимум 40 слепых пар и 60% побед. Синтетические ситуации используются для проверки работы конвейера. Исторические результаты замеров приведены в отчёте о переработке.

Документы T0–T7 ниже описывают историю V1; при расхождениях используйте руководство v0.2. Прежние GPU-замеры V1 не являются результатами V2.

## Общение в группе в v0.2

После `/roast_on` можно прожарить себя: `/roast меня за вечные опоздания` или `@имя_бота прожарь меня`. Свой username тоже подходит.

Для обычного диалога напишите `@имя_бота как дела?` или просто тегните бота. Он ответит без запуска прожарки и учтёт предыдущие реплики. Продолжать можно ответом на сообщение бота или новым обращением по тегу. Прожарка другого участника остаётся доступна через `/roast @username` или тег бота ответом на сообщение участника. `/stop` завершает разговор; действуют прежние лимиты сессии и добровольное участие.

## Исходные требования V1

Первая версия рассчитана на личный запуск в нескольких небольших группах. Она должна принимать новые сообщения только из разрешённых чатов, поддерживать добровольное участие, импорт выбранной истории и генерацию ответа локальной языковой моделью. Владелец выбирает импортируемые данные; само добавление истории не включает участие в прожарке.

Прожарка ограничена короткими ответами и явными правилами остановки. Бот не должен превращать чужие шутки или заметки оператора в факты о человеке. Адреса и контакты, здоровье, сексуальная жизнь, защищённые характеристики, угрозы и выдуманные серьёзные обвинения исключаются из тем для шуток. Молчание завершает сессию и не считается признанием поражения.

В V1 не входят голосовые сообщения, OCR, распознавание изображений, веб-поиск по людям, дообучение модели и векторная база. Для старой истории Telegram нужен экспорт, выбранный оператором: Bot API не предоставляет историю прошлых сообщений группы.

## Стек текущей версии

- Python 3.12 или 3.13 и aiogram 3.
- SQLite с WAL и FTS5 на локальном диске.
- Локальный llama.cpp и Qwen3-8B Q4_K_M; thinking отключён.
- Один процесс приложения и отдельный процесс llama.cpp.
- Ориентир по оборудованию — одна GPU с 16 ГБ VRAM. CUDA — основной вариант для NVIDIA; Vulkan требует отдельной проверки. Скорость заранее не обещается и должна быть измерена на целевом оборудовании.

Python-зависимости закреплены в `uv.lock`. `deployment-lock.json` фиксирует ревизию
модели, SHA256 GGUF и Linux runtime, digest CUDA-образа и реальные замеры.
Реальные переписки, токены и веса моделей не добавляются в репозиторий.

## CLI и локальная диагностика

Список команд доступен через `uv run pozor --help`. Для локальных операций с базой достаточно настроить путь к данным. Запуск модели через Compose и восстановление базы описаны в [руководстве v0.2](docs/13-v02-runbook.md).

```powershell
uv run pozor status
uv run pozor db backup --directory data/backups
uv run pozor db restore --source data/backups/<snapshot>.sqlite3 --destination data/recovery/pozor.sqlite3
```

Restore требует новый путь, отменяет сохранённые pending turns и закрывает сессии;
сетевой запуск не выполняется. Backups содержат переписку: private ACL задаётся
оператором. Ротация по умолчанию — 7 дней при каждом успешном backup.

`uv run pozor doctor` локально проверяет конфигурацию, поддержку FTS5 в SQLite, доступность каталога базы, наличие токена и длину пароля панели. `uv run pozor db migrate` применяет миграции с проверкой контрольных сумм.

`uv run pozor llm smoke` — отдельная opt-in проверка уже запущенного локального llama.cpp: health, alias модели, один slot, размер контекста, tokenizer и structured non-thinking completion на синтетической вводной. Веса не скачивает, в Telegram не пишет. Порядок подключения T4 к T5 описан в [контракте T4](docs/06-t4-inference.md).

## Профили и команды v0.2

`/forget_me` удаляет данные участника в текущей группе и блокирует новый сбор и импорт до явного `/roast_on`. Команда `/roast_off` выключает участие и закрывает активные сессии, в которых прожаривали этого человека. Для локальной диагностики доступны команды
`pozor profile show --chat <id> --target <id>`, `pozor db cleanup`,
`pozor benchmark --suite tests/fixtures/eval.jsonl --output data/offline-eval.json`.
Benchmark по умолчанию offline; `--live --repeat 3` явно включает уже запущенный
локальный llama.cpp на синтетических данных. Telegram не используется.

**Смысловые профили.** При `SEMANTIC_PROFILES_ENABLED=true` (по умолчанию) бот в фоне анализирует доступные собственные сообщения участника с согласием. Модель составляет наблюдения и сводное досье. Они связаны с исходными цитатами. В разделе «История Telegram» оператор может проверить источники, отредактировать и сохранить наблюдения после импорта.

**Карточки цитат V1.** Параметр `PROFILE_CARDS_ENABLED` по умолчанию выключен и управляет использованием старых карточек при подборе контекста. Поиск по сообщениям и подбор исходных цитат проверенных и автоматических наблюдений работают и при выключенном параметре. В контекст также может попасть смысловое досье, если его источники ещё доступны. [История Telegram и смысловые профили](docs/12-telegram-profile-pipeline.md)

`pozor.me` — название проекта, а не допустимый username Telegram. Для регистрации понадобится свободное имя вида `@pozor_me_bot`, созданное через BotFather; такое имя в документации приведено как пример.

Команды `/enable_chat`, `/disable_chat`, `/help`, `/whois`, `/roast_on`, `/roast_off`, `/roast`, `/stop` и `/finish` реализованы. В активной сессии и адресат прожарки, и её инициатор могут продолжить разговор прямым обращением к боту. Импорт сохраняет происхождение сообщений. Исторические команды не исполняются. [Правила согласия и уровни v0.2](docs/13-v02-runbook.md#юмор-и-согласие)
